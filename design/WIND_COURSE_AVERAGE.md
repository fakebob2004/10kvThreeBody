# Direct-drive Wind-GFL — averaged-switch version

`Wind_DirectDrive_Average.slx` is the system-level derivative of the validated
SPWM R2 wind model. It is intended for multi-resource AC coordination studies,
where a 5 kHz switching waveform would add solver cost without improving the
slow electromechanical and grid-control conclusions.

## Preserved physical architecture

```text
wind speed -> Cp(lambda,beta) + rotor inertia
           -> average PMSG/MSC power boundary
           -> physical 1500 V DC link
           -> averaged-switch three-phase GSC
           -> Rf + Lf filter
           -> 0.69/10 kV Y-Y transformer
           -> local PCC measurement -> strong grid
```

The turbine, rotor dynamics, average PMSG/MSC, precharge path, DC capacitor,
filter, transformer, PCC sensor, and grid equivalent are unchanged from SPWM
R2. Only the grid-side bridge actuation is replaced.

The retained Simscape `Converter (Three-Phase)` block uses averaged switching
devices. Its six physical inputs receive continuous duty ratios in the order
`[AH AL BH BL CH CL]`:

```text
d_high = (m + 1) / 2
d_low  = 1 - d_high
```

The duty interface retains one control-step delay to break the instantaneous
controller/plant algebraic loop. There is no triangular carrier, comparator,
or binary switching event in this version.

## Local synchronization and control ownership

The resource uses its own PCC voltage and its own SRF-PLL. No BESS angle,
shared PLL, or cross-resource control signal is used. The active chain is:

```text
local PCC voltage -> SRF-PLL -> control-angle alignment
                  -> P/DC reference -> circular current limit
                  -> dq current controller -> duty interface -> bridge
```

The inherited PLL locks on the negative d-axis and includes a 200 Hz voltage
prefilter. Its control-angle correction is therefore parameterized as

```text
-pi + atan(f_grid / f_prefilter)
```

The nominal 50 Hz angle remains connected only to a monitor and does not drive
the outer or inner controller.

## Interface and upgrade boundary

The model remains a standalone strong-grid commissioning asset. For Stage 2,
the full wind resource should be instantiated as one physical branch and
connected to the common 10 kV bus. Coordination may change resource-level
power or reactive-power commands, but must not directly write `Id*`, `Iq*`,
PLL state, duty ratio, or converter internals.

The average PMSG/MSC subsystem is the future fidelity boundary. It may later be
replaced by a detailed PMSG and machine-side converter while preserving the
physical DC-link and downstream GFL/AC-interface contracts.

## Automated acceptance

Run:

```matlab
run('scripts/build_wind_course_average.m')
run('scripts/validate_wind_course_average.m')
```

The average builder deliberately derives from the locally generated SPWM R2
baseline so the two fidelity levels retain the same physical topology. If
`build/Wind_DirectDrive_SPWM_R2.slx` is absent, first run
`scripts/build_wind_course_spwm_r2.m`; its local course seed remains excluded
from version control together with other external references. No intermediate
SPWM binary or review image is committed.

The accepted R2026a run reports:

```text
WIND_AVERAGE_COMPILE_OK=1
WIND_AVERAGE_STRUCTURE_OK=1
WIND_AVERAGE_PLL_ACTIVE_OK=1
WIND_AVERAGE_DYNAMIC_OK=1

Pmsc       = 3.222013 MW
P_PCC      = 3.184529 MW
Q_PCC      = 0.001007 Mvar
Vdc        = 1494.381 V
PLL f      = 49.99929 Hz
max |mabc| = 0.770893
```

The validator checks the averaged-device selection, removal of carrier/SPWM
logic, active local-PLL path, power balance, PCC reactive power, DC-link
voltage, PLL frequency, and modulation limit.

Simscape can relax initial targets for the DC capacitor and filter currents on
the first initialization solve. This warning is retained in the logs rather
than suppressed. The solver recovers and the structural and dynamic acceptance
checks complete successfully.

## Readability review

The builder renders and the reviewer inspected six views: top-level energy
path, DC link/GSC, GFL control overview, PLL, dq current controller, and
filter/transformer/PCC. Layout changes are generated by the builder, so a fresh
build reproduces the same hierarchy and routing rather than relying on manual
edits to the binary model.
